# v0.4.0 — manual test scenarios

- **Tag:** `v0.4.0`
- **Date:** 2026-10-09
- **Previous version:** `v0.3.0`
- **Scope:** instalator — aplikacja budowana jako VoiceAsystent.app (własna ikona, opis uprawnienia mikrofonu po polsku, podpis ad-hoc) i pakowana do obrazu .dmg z przeciąganiem do Applications; README dla użytkownika i RUNBOOK dla przejmującego projekt. ## 1. Instalacja z obrazu .dmg

### 1.1 Obraz montuje się w Finderze z aplikacją i skrótem do Applications

**Why:** nowe — VA-PLAT-2; test automatyczny montuje obraz z terminala, nie widzi, jak wygląda okno w Finderze.

**Steps:**
1. Dwuklik na `dist/VoiceAsystent-0.4.0.dmg` w Finderze.
2. Spójrz na okno zamontowanego wolumenu „VoiceAsystent”.

**Expected:** w oknie dwa elementy: `VoiceAsystent.app` z własną ikoną (szare kółko z czerwoną kropką) i `Applications` jako skrót do folderu Aplikacje; nic więcej (w szczególności żadnego pliku `.bin`).
**Failure signal:** brak któregoś elementu, ogólna ikona aplikacji (biała kartka / generyczna), plik modelu w obrazie, obraz nie otwiera się.
**Measured value:** rozmiar pliku .dmg w Finderze: ____ MB (oczekiwane ok. 4 MB)

- [x] **Result 1.1** — zgodne z „Oczekiwane”

### 1.2 Po przeciągnięciu do Aplikacji i uruchomieniu pojawia się ikona w pasku menu

**Why:** nowe — kryterium VA-PLAT-2 „po przeciągnięciu do Aplikacji i uruchomieniu pojawia się ikona w pasku menu”; aplikacja po raz pierwszy startuje z bundla, nie z terminala.

**Steps:**
1. Przeciągnij `VoiceAsystent.app` z okna obrazu na `Applications`; wysuń obraz.
2. Otwórz folder Aplikacje, dwuklik na VoiceAsystent.
3. Odczekaj ok. 5 s.

**Expected:** szare kółko w pasku menu, bez okna, bez ikony w Docku, bez ostrzeżenia Gatekeepera (obraz zbudowany lokalnie nie ma kwarantanny); podpowiedź po najechaniu „VoiceAsystent — kliknij albo ctrl+cmd+r, aby nagrywać”.
**Failure signal:** ostrzeżenie „nie można otworzyć”, ikona w Docku, brak kółka po 10 s, komunikat „Wymagane GPU” lub „Brak modelu” w menu mimo pobranego modelu.
**Measured value:** czas od dwukliku do pojawienia się kółka: ____ s

- [x] **Result 1.2** — zgodne z „Oczekiwane”

### 1.3 Pierwsze nagranie z zainstalowanej aplikacji: systemowa prośba o mikrofon z polskim opisem

**Why:** nowe — kryterium VA-PLAT-2 „przy pierwszym nagraniu system prosi o zgodę na dostęp do mikrofonu, a aplikacja ma opis tego uprawnienia w Info.plist”; do tej pory aplikacja korzystała ze zgody terminala.

**Steps:**
1. Kliknij szare kółko (albo ctrl+cmd+r) i zacznij mówić.
2. Przeczytaj okno systemowe, kliknij „Zezwól”.
3. Zakończ nagranie (klik w czerwone kółko / ctrl+cmd+s), wklej cmd+v w Notatkach.
4. Ustawienia systemowe → Prywatność i ochrona → Mikrofon: sprawdź listę.

**Expected:** okno macOS „VoiceAsystent chce uzyskać dostęp do mikrofonu” z tekstem „VoiceAsystent nagrywa Twój głos z mikrofonu, aby zamienić go na tekst i skopiować do schowka. Nagranie nie opuszcza tego komputera.”; po zgodzie transkrypcja wkleja się poprawnie (jeśli pierwsze nagranie trafiło w okno zgody i dało ciszę — powtórz je raz); na liście w Prywatności jest „VoiceAsystent” z własną ikoną.
**Failure signal:** brak okna zgody i od razu powiadomienie „Brak dostępu do mikrofonu”; okno bez polskiego opisu; na liście w Prywatności tylko „Terminal”.

- [x] **Result 1.3** — zgodne z „Oczekiwane”

### 1.4 Powiadomienia podpisane VoiceAsystent, nie Terminal

**Why:** w v0.3.0 powiadomienia pokazywały się jako „Terminal” (aplikacja bez bundla); w bundlu powinny mieć nazwę i ikonę aplikacji.

**Steps:**
1. Nagraj 3 s ciszy przy wyłączonym mikrofonie w Prywatność i ochrona → Mikrofon → VoiceAsystent (wyłącz, nagraj, włącz z powrotem).
2. Spójrz na powiadomienie w prawym górnym rogu i w Centrum powiadomień.

**Expected:** powiadomienie „Brak dostępu do mikrofonu” z nazwą VoiceAsystent i ikoną aplikacji; przy pierwszym powiadomieniu macOS może zapytać o zgodę na powiadomienia — po „Zezwól” kolejne wyświetlają się normalnie.
**Failure signal:** powiadomienie podpisane „Terminal” albo bez nazwy; brak powiadomienia mimo ciszy.

- [x] **Result 1.4** — zgodne z „Oczekiwane”

### 1.5 Wersja w „Informacjach” aplikacji

**Why:** nowe — wersja w Info.plist pochodzi z `git describe`; test sprawdził ją na wartości testowej, nie na prawdziwym tagu.

**Steps:** w folderze Aplikacje zaznacz VoiceAsystent, cmd+i.

**Expected:** „Wersja: 0.4.0 (v0.4.0)”, rodzaj „Aplikacja (Apple Silicon)”, rozmiar ok. 9 MB.
**Failure signal:** „0.0.0”, sufiks `-dirty`, „Aplikacja (Intel)”.

- [x] **Result 1.5** — zgodne z „Oczekiwane”

## 2. Instrukcje z README dla odbiorcy obrazu

### 2.1 Obraz pobrany „z sieci” (kwarantanna) — ścieżka „Otwórz mimo to” z README działa

**Why:** aplikacja jest podpisana ad-hoc, bez notaryzacji; README opisuje, jak przejść Gatekeepera. Lokalny build nie ma kwarantanny, więc trzeba ją nadać ręcznie.

**Steps:**
1. Zakończ zainstalowaną aplikację; skopiuj obraz: `cp dist/VoiceAsystent-0.4.0.dmg ~/Desktop/`
2. Nadaj kwarantannę jak pobranemu plikowi: `xattr -w com.apple.quarantine "0083;00000000;Safari;" ~/Desktop/VoiceAsystent-0.4.0.dmg`
3. Otwórz obraz z Biurka, przeciągnij aplikację do Aplikacji (zastąp), uruchom z folderu Aplikacje.
4. Postępuj dokładnie według sekcji „Instalacja z obrazu .dmg” w README (macOS 15+: Ustawienia → Prywatność i ochrona → „Otwórz mimo to”).

**Expected:** pierwsze uruchomienie zatrzymane ostrzeżeniem macOS; po kroku z README aplikacja startuje i pokazuje kółko; instrukcja w README zgadza się z tym, co faktycznie widać w Ustawieniach (nazwy pozycji).
**Failure signal:** aplikacja startuje bez ostrzeżenia (kwarantanna nie zadziałała — powtórz krok 2), ostrzeżenie bez możliwości „Otwórz mimo to”, instrukcja w README rozmija się z ekranem.

- [x] **Result 2.1** — zgodne z „Oczekiwane”

### 2.2 Czego nie da się sprawdzić na dev

Ścieżka dla macOS 13–14 (prawy przycisk → Otwórz) i zachowanie na macOS starszym niż 13 (LSMinimumSystemVersion powinno zablokować start z komunikatem) — brak takiego komputera. Cisza w tym punkcie nie jest dowodem.

- [ ] **Result 2.2** — brak możliwości sprawdzenia (zaznacz `[x]`, jeśli jednak sprawdzone na innym Macu)

## 3. Barriers — te scenariusze mają się NIE udać

### 3.1 Aplikacja z kwarantanną nie uruchamia się „po cichu”

**Steps:** jak 2.1 kroki 1–3, ale bez kroku 4 — tylko dwuklik.

**Expected:** macOS odmawia uruchomienia (ostrzeżenie o niezweryfikowanym deweloperze), w pasku menu nie pojawia się kółko.
**Failure signal:** aplikacja startuje bez żadnego ostrzeżenia mimo nadanej kwarantanny.

- [x] **Result 3.1** — próba odrzucona zgodnie z „Oczekiwane”

### 3.2 Odmowa zgody na mikrofon w oknie systemowym

**Steps:** Prywatność i ochrona → Mikrofon → usuń VoiceAsystent z listy (przycisk „−”, jeśli jest; inaczej wyłącz przełącznik); uruchom aplikację ponownie; nagraj 3 s; w oknie zgody (jeśli się pojawi) kliknij „Nie zezwalaj”. Na koniec przywróć zgodę.

**Expected:** powiadomienie „Brak dostępu do mikrofonu” ze wskazaniem Prywatność i ochrona → Mikrofon; schowek bez zmian; aplikacja działa dalej; po przywróceniu zgody nagranie działa bez restartu.
**Failure signal:** awaria aplikacji, wymyślony tekst w schowku, konieczność restartu po przywróceniu zgody.

- [x] **Result 3.2** — próba odrzucona zgodnie z „Oczekiwane”
